# Designing MVPs

## When to use

Use this skill to keep the first product version small and testable.

## Workflow

1. Define the MVP goal.
2. Identify must-have features.
3. Identify nice-to-have features.
4. Remove features that do not validate the main risk.
5. Suggest a 2 to 4 week MVP scope.
6. Suggest one manual or no-code alternative if possible.

## Output format

```markdown
## MVP Scope

### MVP Goal

### Must-Have Features

### Later Features

### What Not To Build Yet

### 2-4 Week Build Plan
```
